# DSV Driver 앱 인증

DSV 전용 Driver 앱은 기존 CLEVER Routes 앱의 Shopify 초대 및 전화번호 + PIN 인증을
사용하지 않는다. 가입은 로그인 ID, 비밀번호, 이름, 국내 휴대전화 번호, 주민등록번호
앞 7자리를 받고 이후 로그인은 로그인 ID와 비밀번호만 사용한다.

## API

| Method | Path | 결과 |
| --- | --- | --- |
| `POST` | `/api/dsv/driver/auth/register` | 계정 생성, 정확히 일치하는 DSV 배송원 연결, 30일 갱신 세션 발급 |
| `POST` | `/api/dsv/driver/auth/login` | 계정 로그인, 새로 등록된 일치 배송원 재탐색, 세션 발급 |
| `POST` | `/api/dsv/driver/auth/refresh` | 유효한 refresh token으로 비밀번호 재입력 없이 15분 access token 갱신 |

로그인 ID는 소문자 영문, 숫자, `.`, `_`, `-`만 허용하며 4~40자다. 비밀번호는
8~128자, 이름은 1~80자, 휴대전화 번호는 `01`로 시작하는 숫자 10~11자리,
주민번호 앞자리는 숫자 7자리다. 전화번호 구분기호와 로그인 ID 대문자는 서버 경계에서
정규화된다.

## 연결 규칙

계정은 다음 조건이 모두 같은 활성 DSV 배송원만 확보한다.

1. 공백을 제거한 이름이 정확히 같다.
2. 숫자만 남긴 휴대전화 번호가 정확히 같다.
3. 같은 서버 비밀키로 계산한 주민번호 앞 7자리 HMAC 지문이 정확히 같다.
4. 해당 배송원이 아직 다른 계정에 연결되지 않았다.

가입 시 일치 배송원이 없으면 계정은 `UNLINKED`로 만들어진다. DSV 운영자가 배송원을
나중에 추가하면 다음 성공 로그인에서 다시 같은 조건으로 연결한다. 일부 값만 같은 배송원이나
이미 다른 계정이 확보한 배송원은 연결하지 않는다.

## 보안 및 저장

- 비밀번호는 계정별 salt를 사용한 `scrypt` 해시만 저장한다.
- 주민번호 앞 7자리는 `DSV_DRIVER_IDENTITY_SECRET` 기반 HMAC-SHA256 지문만 저장한다.
- 로그인 실패 메시지는 존재하지 않는 ID, 오입력, 잠금 계정을 구분하지 않는다.
- 비밀번호 5회 연속 실패 시 15분 잠금한다.
- 가입은 IP당 15분에 5회, 로그인은 IP당 15분에 10회로 제한한다.
- access token은 15분, refresh token은 30일이며 응답 `use`는
  `dsv_driver_account`다.
- 모바일 앱은 비밀번호가 아닌 refresh token과 세션 표시 정보만 OS 보안 저장소에 보관한다.
- 로그아웃 시 기기의 저장 세션을 삭제하고, 갱신 세션이 폐기·만료되면 다시 로그인한다.

## 운영 활성화와 테스트 신원 시드

인증 라우트는 `CLEVER_DSV_DRIVER_AUTH_ENABLED=true`일 때만 등록된다. 이 값이 켜진
환경에서는 `JWT_SECRET`과 32자 이상의 `DSV_DRIVER_IDENTITY_SECRET`이 누락되면 서버가
기동을 거부한다.

운영 양우진 배송원에 테스트 주민번호 앞 7자리 지문을 넣는 일회성 작업은 빌드 결과의
`dist/scripts/seed-dsv-driver-test-identity.js`만 사용한다. 스크립트는 production 환경,
change-control 승인 문자열, 고정된 배송원 ID와 이름이 모두 맞아야 실행되며 기본은
dry-run이다. 실제 반영은 `--apply`를 함께 전달해야 한다. 기존 지문이 다른 경우에는
덮어쓰지 않고 중단하며 출력에는 전화번호, 주민번호 또는 지문을 포함하지 않는다.
